## Commands

- **Typecheck:** `npm run typecheck` (run `npm install` once first). It checks against the engine types Claude Code writes into `.claude-plugin/types/` whenever it loads the mod, so load the mod once (below) on a fresh clone or after a Claude Code update.
- **Single test file:** `claude plugin test` has no file filter; it always runs every `*.test.ts` under the folder. The whole suite takes about a second, so run it.
- **Full suite:** `npm test` (same as `claude plugin test .`).
- **Load in a session:** `claude --plugin-dir .` (hot-reloads on save). Then `/squishys` toggles the pane.
- **Art preview:** `npm run preview` writes `out/art-preview.html` (gitignored) from the current kit. Publish it as an Artifact with `capabilities: { db: {} }`; see "Art preview" below.
- **Validate before a PR:** `claude plugin validate .` (the marketplace) and `claude plugin validate .claude-plugin/plugin.json` (the manifest, hooks and `$.state` contract).

## Mod conventions

- `hooks/register.tsx` only wires features. Each feature is a module in `src/` exporting `register<Feature>(on)`. Pure modules (the roller, composer, roster layout) take plain data, never `$`, and their tests call them directly (with seeded randomness where they roll). Everything else is tested through the mod test kit in `tests/`, with shared inputs in `tests/fixtures.ts`.
- One hook per event per plugin: the engine refuses a second unmatched `on('tool.call')` anywhere in the module graph. A new behaviour on an event already hooked joins that event's existing hook. Where it needs `$` functions of another file, that file adds a matched hook instead, with a matcher every event fits (`src/agents.ts` hooks `session.start` with `{ isInteractive: [true, false] }`).
- The engine reads `$.state` references off each file statically, so every file that reads or writes a value declares its own `atom({ plugin: 'squishys', key }, initial)` const; an imported atom fails to load. Each value is declared in `types/index.d.ts`.
- Every `$.state.get` of one dispatch reads one moment, whatever is written meanwhile (the types say so), so a read after `await next(e)` misses what an event raised inside `next` wrote: a permission prompt during a `tool.call`, as `tests/needs-you.test.ts` shows. There, `src/agents.ts` keeps the `asking` set and calls `setState` with `current`, which writes without reading first.
- `$` is followed only into functions declared in the same file as the hook, never across an import. Logic shared between feature files takes plain data (as `settingsFrom` and `withModelDefault` in `src/settings.tsx` do), and the hook makes the `$` calls itself.
- Drawing hooks return `next(e)` unless `e.surface === 'terminal'`.
- The pane shows one mode at a time: the `mode` value in `$.state` (`PaneMode` in `types/index.d.ts`). Each mode is a feature module with its own `ui.render` hook on `{ component: 'Pane', requestId: 'squishys' }` (spelled out, so the engine can read the matcher) that draws only while `mode` names it and returns `next(e)` otherwise. Several matched hooks on one event are allowed. A new mode adds its name to `PaneMode` and a module like `src/settings.tsx`.
- A plugin's registrations nest in the order `hooks/register.tsx` makes them, first outermost, and features rely on it: the agent tracker comes before the focus view's feed hooks, so an agent first seen through a tool call is recorded before the feed looks it up, and the pane's render hook comes before every other mode's, so it can animate what they draw.
- Picking a squishy is one handler: the `ui.press` hook in `src/focus.tsx`, matched on `element: /^squishy-/`, answers a press on any pane or band Button keyed `${PICK_PREFIX}<agent id>` (`PICK_PREFIX` in `src/pane.tsx` is `squishy-`) by opening that agent's focus view; a press from outside the pane (`pickedOutsidePane(e)`: the band's) opens the pane too. A new place to pick from (the list opened from the overflow count, the band) keys its Buttons so and needs no handler of its own; their `onPress` stays a no-op. Beside it, not a second pick, `src/pane.tsx` has a matched `ui.press` hook on `{ plugin: 'squishys' }` that shuts the overflow list on any press but the overflow count's. The pane registers before the focus view, so its hook is the outer one: it shuts the list, then `next(e)` reaches the pick.
- The focus view's feed is a `StateFamily` (`activity` in `$.state`, one member per agent id, read as `atom({ ...activity, id }, [])`), so one agent's activity never redraws another's focus view. It keeps the latest `FEED_ROWS` rows and only the latest final answer; `fedAgentIds` lists the agents with a feed, so the feeds of agents the tracker no longer knows are emptied. Matched hooks in `src/focus.tsx` on `{ agentId: /./ }` fill it. Thinking… is drawn from the agent's state, not kept in the feed. Text from an agent is made printable (no control characters but tab and newline) before it's drawn, since one control character makes the engine refuse the whole tree.
- Experimental features sit behind a setting that is off by default (absent from the stored settings until turned on) and whose label starts with "Experimental". The live model switch lives in `src/model-switch.ts`, which alone writes `switchedModels` in `$.state` (per agent: a `Model` alias and whether a request has gone out on it). The focus view only reads it and draws the picker, keyed `model-switch-<agent id>`, whose pick a matched `ui.select` hook in `src/model-switch.ts` answers; it ends every switch by its own matched `ui.select` hook on the settings Select. Its matched `turn.step` hook sits inside the tracker's and rewrites only a switched agent's requests (`next({ ...e, model })`, `effort` left out). Before each one it checks that the setting is on, the agent hasn't ended and the allowlist names the model, and ends the switch otherwise. A switch also ends with the agent's run and on `/clear`, `/resume` and a branch.
- Model ids and the allowlist: the engine resolves an alias and checks it against the allowlist for `agent.spawn` and `$.model.complete`, but `TurnStepInput.model` promises neither, and nothing on `$` maps an alias to a model id (`$.session.model()` gives only the orchestrator's). `$.settings.read()` is an untyped record. So the switch sends an alias, and while Claude Code's `availableModels` setting is set, only an alias that setting names; an entry naming a full id allows no alias. Never hard-code model ids. Model pickers take their options from `modelOptions` in `src/settings.tsx`, so they all label and order models the same way.
- Stop's rules and the agents it is stopping live in `src/stop.ts` (plain data). `src/focus.tsx` (the `ui.press` hook on `element: 'stop'`, and the note) and the agent tracker's hooks make the `$` calls. A press stops when it comes within `STOP_CONFIRM_MS` of the `armedAt` in `stopControl`, never by a timer, so an armed Stop survives a reload as harmless. The timer only redraws its note away. The hook awaits the `TaskStop` call inside its own dispatch: under the test kit, a `$.tool.call` the mod makes after its hook has returned skips the mod's own `tool.call` hooks. The tracker's hook is what makes the squishy of an agent `TaskStop` stopped Squished, once the agent list shows it ended. `TaskStop` names a teammate by its `teammateId` (or `name`), never its `id`. When `TaskStop` doesn't stop the agent, `holdBack` marks it: the tracker's `tool.call` and `turn.step` hooks (the outermost) refuse its tool calls and answer its next model request without the model. The marks change only in `setState`, as an agent ends or resumes, plus a `turn.step` of an ended agent (a resume) and a rebuilt session. Nothing the focus view draws about a stop is kept in `$.state`, so a reload leaves no stale note.
- A `Button` `hotkey` is one digit or one lowercase letter; the engine refuses anything else, so the spec's `,` for settings is `o`, and `r` returns to the roster.
- While an `Input` has the focus, every printable key goes to it alone (`InputProps` in the engine types; seen in a session for #13, where typing `r stop o 1` into the redirect Input pressed nothing). So the focus view keeps its hotkeys while the redirect Input is drawn. Esc takes the keys back. The engine draws a colon after an `Input`'s `label` (seen in that session: `Redirect:` drew as `Redirect::`), so leave the colon off.
- A redirect goes to a running agent with `$.session.append` and to an ended one with `$.session.send`, which resumes it (`deliver` in `src/focus.tsx`). Both carry the text wrapped as the user's (`fromUser`), since a bare sent message reads to the agent as a peer's. The only fallback from append to send is a refusal for want of a running loop (Claude Code's `no running loop is <id>`). The test kit has no implementation of a plugin's `$.session.append`: no stub and no other plugin's hook reaches it, and it always rejects with `no implementation for session.append`. So the tests see a running agent's redirect refused, and the append itself was checked only in a session. The kit also drops an `Input` submit that no `change` came before, so tests type a `change` first.
- The latest redirect's delivery (`delivery` in `$.state`) shows in its agent's focus view until Back, a pick of another agent, or the agent ending (its `turn.complete`) or resuming (its state is no longer ended, or no longer running, as when it was sent). `/clear`, `/resume` and `/branch` reset it with every other `$.state` value.
- Lasting values live in `$.store` (settings under `settings`, each agent's squishy key under `agentSquishys`, the partner under `partner`, the Squishydex under `squishydex`; see below). The test kit leaves the store unanswered, and a hook whose store call goes unanswered is skipped, so every test that spawns an agent answers it with `mock.store(on)`, or with `stubStore(on)` from `tests/fixtures.ts` to read back what was saved.
- The pure modules (`src/kit.ts`, `src/roller.ts`, `src/composer.ts`, `src/raster.ts`, `src/states.ts`, `src/seeded.ts`, `src/slots.ts`, `src/face.ts`, `src/verbs.ts`, `src/squishydex-record.ts` and the kit data) never import from `claude-code`, so tools outside the mod (the art preview) use them as they are. Those are the only modules a tool may import; a tool never imports test code. The mod rolls with `cryptoRandom` from `src/roller.ts` (`crypto.getRandomValues`); tests and the art preview pass `seeded(n)` from `src/seeded.ts`.
- `claude plugin validate` wants `types/index.d.ts` self-contained (no imports), so a type it shares with a pure module (`Squishy`, `Rarity`) is written out in both. Change both together: the mod hands values both ways between them, so the typecheck fails if they drift.
- A squishy's state lives on its agent in the `agents` value (`state`), set by the agent tracker in `src/agents.ts`. The rules about states (which have ended, which move, which state an end maps to, what an answered prompt leaves) live only in `src/states.ts`. Every mode draws a squishy's picture through `animatedPicture(agent, size)` from `src/pane.tsx`, in a Raster keyed `pictureKey(agent.id, size)`, which draws it at the animator's current frame and has the animator repaint it; the pane's own render hook (the outermost) starts the animator after whichever mode drew. The band passes its own `e.requestId` as a third argument, so the animator blits to the band, and a matched `ui.render` hook on `{ component: 'AbovePrompt' }` in `src/pane.tsx`, outside the band's, starts the animator after the band drew. Animation frames only ever go out as `$.ui.blit` from the animator in `src/pane.tsx`: a frame never writes `$.state` or calls `$.ui.invalidate`.
- Mod tests read a squishy's state from its picture: `watch(ui, agentId)` (or `spawnAndWatch($)`) from `tests/pictures.ts` finds the squishy a just-spawned slot shows, and its `state()` names the pose the slot shows now, at any frame.
- The test kit drops the `key` of a `Text`: find a Text by `text`, or key the `Box` around it. It has no implementation of `$.ui.scroll` (a `ui.scroll` hook doesn't answer it), so wrap the call in `try` and don't test the scroll itself.
- `/clear`, `/resume` and `/branch` reset every `$.state` value to its default, and `session.start` doesn't fire again, but `classic.SessionStart` does, with `source` `clear`, `resume` or `fork` (the mods docs, "Load a saved value again after /clear": https://code.claude.com/docs/en/plugins/mods/interface#load-a-saved-value-again-after-clear). Compaction fires it with `compact` and keeps `$.state`. `src/rebuild.ts` rebuilds the roster on all four from `$.agent.list()`, each agent's state from `stateOfStatus` in `src/states.ts`, checking against the roster as it is inside its `update`. Each agent's squishy is kept in the store as `Remembered` pairs (`[agentId, squishyKey]`) under `agentSquishys`: only the key, which `squishyOf` in `src/roller.ts` turns back into the squishy, or nothing once the kit lacks a part. Every write to it goes through `rememberSquishys` in `src/rebuild.ts`, one queue per process that reads, merges and writes, with the hook passing its own store calls in (`StoreCalls`, below). Every session shares the store, so pairs are dropped by age past `REMEMBERED_AGENTS`, never for missing from one session's list. A feature with other `$.state` values to restore adds its own matched `classic.SessionStart` hook.
- Tests stand for `/clear` by firing `$.classic.SessionStart` (answered by `stubSessionStart`) without `session.start`: the kit starts every test with `$.state` at its defaults. `stubAgentList` takes a Map of statuses, or a list of agents with their own descriptions. `squishyIn(cells, name, state)` from `tests/pictures.ts` finds a squishy shown in any pose, as a rebuilt one may be.
- To check that none of the mod's hooks fails, `tests/rebuild.test.ts` loads `WATCHER`, an inline `prepend` plugin that toasts each squishys link `next.trace` reports as anything but returned or passed. An inline plugin's source runs apart from the test, so it shares no variables with it: everything it uses is inside `register`, and it reports through a call the test stubs.
- No test walks every squishy the kit can make, since the real kit makes thousands: cover every part once (`eachPart`), and keep spawns in a test to a handful.
- While a `turn.step` stream a test opened is still open, the kit waits out a timeout before each act (about 500ms for `find`, 1000ms for `clock.settle`). Read the first piece with `await stream.next()`, keep acts to a minimum until the stream is drained, and use `clock.advance`, which doesn't wait.
- Under `mock.clock` the agent list is checked every `AGENT_CHECK_MS` while any agent runs. A check that goes unanswered is skipped, so answer `agent.list` (`stubAgentList`) only where the test is about it. The kit can't reload the mod; a test stands in for a reload dropping the timers by refusing `clock.every` periods with its own hook (see the hot reload test in `tests/states.test.ts`).
- The roster layout is `layoutRoster` in `src/slots.ts`: the pane's placement, body columns and rows, the slot cap and the agents in; the agents in slots and the overflow out. The pane keeps the slots it last drew so squishys stay put. `squishysOnScreen()` in `src/pane.tsx` names those agents plus any other the pane last drew (the focus view's), and the agent tracker and the rebuild after /clear roll against `liveSquishys` (running agents plus those on screen), so an ended agent that is nowhere on screen returns its squishy to the pool. Which ended squishys give up their slots first (Asleep, then Squished) is `SLOT_GIVING_ORDER` in `src/states.ts`. Slot sizes derive from the composer's `PICTURE_SIZE` through `PICTURE_COLUMNS`/`PICTURE_ROWS`, and every gap the pane draws with is a named constant there; tests size a pane with `roomFor(placement, across, down)` and `paneSized` from `tests/fixtures.ts`, never with literal cell counts, and use `MAX_SLOTS` for the cap.
- The pane opens unasked at the session's first agent: the agent tracker's `assignSquishy` in `src/agents.ts`, whether the agent came through `agent.spawn` or the `tool.call` fallback, opens it with `OPEN_PANE` from `src/pane.tsx` (never `focus`) unless `$.ui.panes()` lists it already. Claude Code places such an open only from 144 columns (110 once the user has opened it before) and otherwise leaves it open but unplaced (`isPlaced` false). The band, `src/band.tsx`, draws only while the pane is unplaced, there are agents and `e.props.hasSurvey` is false, and returns `next(e)` otherwise. Which agents it shows and its overflow are `layoutBand` in `src/slots.ts` (pure, tested in `tests/slots.test.ts`): running ones first, then ended ones in reverse `SLOT_GIVING_ORDER`, as many as leave room for the "+N" and the hint, mini pictures from `BAND_PICTURE_ROWS` rows and the Names alone below. Its sizes derive from `PICTURE_COLUMNS` there. Band Buttons never carry a `hotkey`: a bare digit in an empty prompt presses a band Button, which would swallow the first keystroke of a message. `/squishys` and a pick from outside the pane (`pickedOutsidePane(e)` in `src/focus.tsx`: the band's) open the pane asked, so it's placed at any width; a refused open shows a toast (`openRefused`), and either way they call `$.ui.invalidate('ui.render')`, since nothing the band reads changes. `/squishys` closes only a placed pane. Band tests size the band with `bandSized` and stand in for Claude Code's placement with `stubPanes`, both in `tests/band.test.ts`.
- The overflow list shows while `overflowOpen` is set and the overflow isn't empty. A drawing never writes `$.state`: one that finds the overflow empty under an open list notes it in the pane module (`listOutlived`), so the list stays shut until asked for again. The flag itself is cleared by events: any press in the pane but the overflow count's, and `session.start`.
- The partner (`src/partner.tsx`) is kept in the store under `partner` as its species and the palette it was picked in (`{ body, face, palette }`), so it can later become any species met and a change to the kit's palettes doesn't recolor or rename it. `partnerFrom` turns the stored value into its squishy through `speciesSquishy` in `src/roller.ts`, the one rule for drawing a species (the mod's starters, the partner and the art preview's starters): in the given palette (the kit's first once it's gone), the bare accessory, never shiny; nothing once the kit lacks the body or face. A species is `Species` in `src/kit.ts`. `session.start` and `classic.SessionStart` (clear, resume, fork) put `mode` on `starter` while no partner is saved, so the pane opens on the starter pick; a store that can't be read leaves the roster. The partner is no agent: the roster passes its squishy to `layoutRoster` (`partner`), which pins it in slot 0 on top of the slot cap (the cap counts agents' slots; `partnerSlot` says whether the pane had room) and shares the rest among the agents. The starter pick wraps its starters to as many across as `slotsThatFit` the pane. Its picture is still (`stillPicture`, a Raster keyed `PARTNER_PICTURE`, never `animatedPicture`), its Button is keyed `partner` (not `PICK_PREFIX`, so the agent pick never sees it) and returns the pane to the roster from the focus view, and it's marked in the main view while `view.agentId` is absent. Every roll passes the partner's squishy to `liveSquishys`, so no agent gets it. The mod's randomness can't be loaded from a test (each plugin's environment is its own, so stubbing `crypto` doesn't reach the mod). Tests that start a session (`session.start` or `classic.SessionStart`) with a store answer it with `PARTNERED` from `tests/fixtures.ts` unless they're about the starter pick, and count agents' pictures by their `picture-` key, since the partner's slot adds a Raster.
- The spinner (`src/spinner.tsx`) hooks `ui.render` on `{ component: 'Spinner' }` and draws only on the terminal. The engine's `requestId` there is the spinner id, the same every turn, and the docs say a site is drawn again when its props change or the terminal's width does, never on a timer ("Redraw a site": https://code.claude.com/docs/en/plugins/mods/interface#redraw-when-something-changes), so it draws again on each change of `mode` or `message`. A turn is told by `word` (Claude Code samples one per turn): `pickVerb` in `src/verbs.ts` (pure, `VERB_ODDS` from `SQUISHY_VERBS`; the hook passes `cryptoRandom`) picks once per spinner id and word, kept in the module, and a new word picks again. The hook calls `next` first, with the verb as `word`, then, inside one `try` that falls back to Claude Code's spinner untouched, draws the partner's tiny face beside it in a row Box, but only on a spinner id no agent in `agents` has: the partner stands for the orchestrator, so an agent's spinner gets verbs and no face. The face is colored half-block `Text` (no Raster there), from `tinyFace` in `src/face.ts`: the still picture (`stillPixels` in `src/composer.ts`) cropped to where the face part draws, shrunk by whole steps to `FACE_ROWS` rows, each block showing an eye, else a mouth, else a blush pixel by the face part's keys (the 4-color art shares their colors with the outline and shade), else its most common color. The Raster packer and the face share `halfBlockRows` in `src/raster.ts`, and every `#rrggbb` comes from `hexColor` there. Unverified: the types say a Text color is "a theme key or a raw color" and the docs show only names (`'red'`), so whether the terminal paints `#rrggbb` is for the smoke test (#20) to check; the test kit accepts it. Spinner tests stand in for Claude Code with a `ui.render` hook on the Spinner beneath the mod and step through turns with `redraw`.
- A module that keeps a value in the store names its own key and takes the hook's store calls as `StoreCalls` (`src/squishydex-record.ts`): `{ get: key => $.store.get(key), set: (key, value) => $.store.set(key, value) }`. The engine refuses `$.store` (any noun of `$`) passed as a value, so the hook spells its calls out.
- The Squishydex's record is the pure `src/squishydex-record.ts`, kept in the store under `squishydex`. It stays compact because every session shares the store's 4 MiB. Per species it keeps the first-met date (`$.clock.now()`) and the variant keys seen, first seen first. Per legendary id it keeps the first-met and first-shiny dates. Entries are objects, so more can be kept per entry (#18's NEW mark) without a new shape. Species and variant keys are built and read only by `speciesKey`/`speciesOfKey` and `variantKey`/`variantOfKey`, and squishy keys only by the roller's `assembledKey`/`legendaryKey` and `squishyOf`, tests too. Every species is `everySpecies(kit)` in `src/kit.ts`. Every write goes through `recordMet`, one queue per process that reads, merges and writes like `rememberSquishys`. It reads the clock inside its `try`, only when something is new, and writes nothing otherwise, so a failed clock or store loses only that sighting. The store has no atomic update, so two sessions recording at once can drop an entry, which comes back the next time that squishy is met. Recorded:
  - every squishy rolled for an agent, after its hook's `next(e)`, so recording never holds up a tool call or the agent's state: the tracker's `agent.spawn` and `tool.call` hooks, and the rebuild after `/clear`.
  - the partner, as a starter is picked or made from a species' card, and at `session.start` when a saved partner isn't recorded yet. `PARTNERED` in `tests/fixtures.ts` has its partner recorded already.
- The Squishydex mode (`src/squishydex.tsx`) lists every species, then the legendaries, numbered in that order, as pages of places: a mini picture over a Name or number, at the band's place size (`DEX_PLACE_COLUMNS`/`DEX_PLACE_ROWS`). As many places as fit go on a page, and `n`/`p` turn pages (`squishydexPage`). A met species is drawn in the palette it was first met in. An unmet species is its shape in `SILHOUETTE_COLOR`, a slate that reads on dark and light terminals (the test checks 3:1 contrast against both). An unmet legendary is "???". Each met place has a Button keyed `squishydex-pick-<place key>` (a species key, or the legendary's squishy key), with a digit hotkey in page order, that opens its card (`squishydexPicked`).
  - A species' card lists the variants met and the first-met date. "Make partner" (`m`) saves `{ body, face, palette }` under `partner`, in the plain palette picked on the card (`squishydexPalette`, the first met by default).
  - A legendary's card shows the first-met and first-shiny dates and has no "Make partner", since a partner is a species.
  - `b` returns to the pages from a card, and `r` returns to the roster, or to the starter pick while no partner is saved. The roster's `d` button (keyed `squishydex`, its `onPress` a no-op) and `/squishydex` (registered `immediate` beside `/squishys` in the pane's `session.start`, and opening the pane asked) are answered in `src/squishydex.tsx`.
- A Button with a hotkey draws as `x: label`, so widths are budgeted with `buttonColumns(label, hotkey)` from `src/slots.ts`, never from the label alone. Rows of buttons and counts that may not fit across are laid out with `linedUp`, as many to a row as fit, and the rows they take are budgeted: the roster's docked footer (`footerRows`, with every button there and the overflow count at its widest), and the Squishydex's counts, footer and card actions. The inline roster's footer column is `FOOTER_COLUMNS`, its widest button. A pane too short for the counts and a row of places leaves the counts out.
- The version lives only in `.claude-plugin/plugin.json`.

## Art preview

- `tools/preview/` is development only and the mod never loads it. `items.ts` lists the items and draws them through `compose` and `roll` (tested in `tests/preview.test.ts`), `page.ts` writes the HTML, `client.js` is the page script, and `build.mjs` runs it all under Node's built-in type stripping, with a resolve hook that adds the `.ts` the mod's imports leave off. It imports only the pure modules, never `claude-code`.
- Item ids stay the same while the kit keeps its part ids: `body/<id>`, `face/<id>`, `palette/<id>` and `palette/<id>/shiny`, `accessory/<id>`, `sample/<squishy key>` (seed 1), the legendary's squishy key (`legendary/<id>`, `legendary/<id>/shiny`) and `starter/<body>/<face>`. Plain and shiny are separate items with their own verdicts.
- Verdicts live in the published page's database, collection `verdicts`, one document per item: `{ item, verdict: 'keep' | 'redo' | null, notes, art, updatedAt }`. `art` is the fingerprint (FNV-1a over the pixels, 8 hex digits) of the picture the verdict was given on. The page shows a verdict only while `art` matches the current picture; after a redraw the item reads "changed since your verdict" and counts as undecided. The document id is the item id with `/` as `:`, and any other character outside `A-Z a-z 0-9 _ - . @ +` (including `~`) as `~` and four hex digits of its code point. Read verdicts back with the `ArtifactData` tool (`list` on `verdicts`). Republish to the same artifact URL after redrawing, so the verdicts stay with the page. Deleting a document sets its item back to undecided.
- Opened without the database (as a local file), or after the store refuses a save, the page keeps verdicts in the browser with a notice, and shows them as JSON at its foot to paste back.
